# Memory layers for AI agents exposed over MCP — competitive landscape (state as of 2026-10-11)

Research scope: products/projects that let multiple AI clients (Claude Desktop/Code, ChatGPT, Cursor, Gemini CLI, Copilot, Windsurf, …) read AND write a shared persistent memory over MCP, compared against the OmniMind feature set (hybrid vector+FTS+trigram retrieval, temporal validity, supersede-with-provenance, idempotent writes, multi-tenant + per-agent scoped keys, structured decision/commitment/task/person/project entities, background "cortex" jobs, built-in graph visualization).

Method notes / caveats for the report writer:
- Primary sources reached directly: GitHub repo pages (github.com), the official MCP registry API (registry.modelcontextprotocol.io), PyPI JSON API, platform.claude.com. Most vendor marketing/doc domains (mem0.ai, getzep.com, cognee.ai, supermemory.ai, mastra.ai, letta.com, help.openai.com, news.ycombinator.com, huggingface.co, reddit.com) were **not fetchable from this sandbox** (proxy policy denial / DNS). ## KQ1. Per-product profiles: self-hosted vs SaaS, pricing, license, stars/activity, MCP transport, remote-MCP auth, documented clients

### Takeaway
Every "serious" entrant now has some MCP story, but they split into three camps: (a) hosted-first vendors with a remote Streamable-HTTP MCP endpoint behind OAuth or API key (Zep, Supermemory, Mem0 cloud, Honcho, Hindsight Cloud, Memori), (b) open-source engines whose MCP server is a self-run process over stdio/HTTP with little or no built-in auth (Graphiti MCP, Cognee MCP, Basic Memory, doobidoo, MemMachine), and (c) frameworks that are not really MCP memory servers at all (LangMem, Mastra, memU, Letta post-March-2026). Pricing has converged on usage/credit models with a free tier and a $19–$20/mo entry plan (Mem0 Starter $19, Supermemory Pro $19, Letta Pro $20, Basic Memory Cloud $15–19); Zep is the outlier at $125+/mo.

### Inferences
- Remote-MCP auth has bifurcated: consumer/prosumer hosted products (Zep, Supermemory, Hindsight Cloud, many registry entrants) use OAuth 2.1 browser flows; developer-oriented hosted products (Mem0, Honcho) still lead with bearer API keys; OSS self-run MCP servers (Graphiti, Cognee, Basic Memory) ship with **no auth at all** and expect a reverse proxy or stdio. A self-hosted system with per-agent scoped keys is therefore ahead of the OSS field but behind Zep/Hindsight on OAuth.
- The GitHub star figure for Hindsight (48.3k) is higher than for mem0's peers of comparable age; it is what github.com rendered and could not be cross-checked via the API. Treat as "reported."
- Letta has effectively exited the "shared memory server over MCP" category as of March 2026; LangMem is dormant (last PyPI release Oct 2025); Mastra and memU are framework/CLI-level memories rather than cross-client servers.

## KQ2. Feature support: temporal validity, supersession with provenance, structured entities, multi-tenant isolation, per-agent scopes, idempotency keys, contradiction detection, scheduled background intelligence, graph UI, hybrid retrieval

### Takeaway
Only Zep/Graphiti ships a true bi-temporal model (valid_at/invalid_at + created_at/expired_at with episode provenance) as a first-class API; Supermemory and Cognee have partial temporal features (expiry/versioning; event timestamps). Hybrid lexical+vector retrieval is now table stakes (Graphiti, Honcho, Hindsight, Basic Memory, Supermemory, MemOS, several HN entrants), but **nobody documents trigram/fuzzy matching**. Structured business entities (decisions, commitments, tasks, people, projects) are essentially absent — memory products model "facts/entities/edges" or "notes", not decision/commitment objects. **No vendor documents an `Idempotency-Key` for memory writes.** Scheduled background intelligence exists in pieces (Supermemory "Dynamic Dreaming", Honcho `schedule_dream`, Hindsight consolidation, doobidoo consolidation, Mastra Observer/Reflector) but no product ships weekly memos or contradiction-alert jobs as user-facing artifacts.

## KQ6. What is clearly NOT solved by any of them

### Takeaway
Across the field, the unsolved items most relevant to OmniMind's positioning are: client-supplied idempotency; first-class business entities (decisions/commitments/tasks) with lifecycle; scheduled, persisted intelligence artifacts (weekly memos, contradiction alerts, reflection capsules) as opposed to ingest-time reconciliation; per-agent (not just per-user) scopes in OSS; trigram/fuzzy lexical retrieval; and neutral benchmarks.

### Cited Findings
- Idempotency: no vendor doc; only content-hash dedup (Cloudflare, Memir) — [developers.cloudflare.com/agent-memory](https://developers.cloudflare.com/agent-memory/concepts/how-agent-memory-works/), [pypi memir](https://pypi.org/project/memir)
- Contradiction detection "still underdeveloped" — [arXiv 2603.07670](https://arxiv.org/pdf/2603.07670); open issue in Redis agent-memory-server — [#196](https://github.com/redis/agent-memory-server/issues/196)
- Weekly digest / scheduled reflection appears only as a use-case blog or design proposal, not a shipped feature — [hindsight use cases](https://hindsight.vectorize.io/blog/2026/07/27/agent-memory-use-cases), [hrustalq/knowledge #70](https://github.com/hrustalq/knowledge/issues/70)
- Behavioral pattern learning (vs fact storage) is a recurring user complaint — [HN 46891715](https://news.ycombinator.com/item?id=46891715)
- Per-tool memory scoping question unanswered in community discussion — [mbsamuel.substack.com comments](https://mbsamuel.substack.com/p/who-controls-the-context/comments)
- Cross-platform live sync between native memories does not exist; only snapshot import — [support.claude.com import article](https://support.claude.com/en/articles/12123587-import-and-export-your-memory-from-claude)
- OSS MCP servers lack auth (Graphiti, Cognee) — READMEs cited above
- Benchmark comparability — [zep-papers #5](https://github.com/getzep/zep-papers/issues/5)
- Memory poisoning / prompt-injection via memory tools is an active risk (Graphiti CVE; Zep's own poisoning guide) — [cvefeed CVE-2026-32247](https://cvefeed.io/vuln/detail/CVE-2026-32247), [blog.getzep.com/defending-agent-memory-poisoning](https://blog.getzep.com/defending-agent-memory-poisoning/)

### Inferences
- "Self-hosted bi-temporal memory with OAuth/scoped MCP + structured business entities + cron intelligence + graph UI" is **not commoditized as a bundle**; its individual parts are each available somewhere (Zep: temporal+graph UI+OAuth; Hindsight: scoped keys+hybrid+consolidation; Honcho: AGPL self-host+Postgres/pgvector+BM25; Supermemory: dreaming+expiry). The defensible gap is the entity model (decisions/commitments/tasks/people/projects) plus persisted cortex artifacts plus idempotency — none of which the memory vendors treat as core.
- Risk to uniqueness: Zep's Memory MCP (Aug 2026) and the flood of OAuth-secured hosted "one memory" servers show the *distribution* layer is solved; the data-model and governance layers are where a self-hosted product must prove value.

### Gaps
- Could not verify whether Zep Enterprise ABAC supports per-agent *scopes* (read vs write per entity type) comparable to OmniMind's `memory:read,decision:write,task:write…` scheme.
- Trigram retrieval absence is an absence-of-evidence finding (no README mentions it), not confirmed by code inspection.
